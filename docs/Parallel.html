Large data and parallel computing

Where the time goes

For each spatial kernel, SIGNAL first computes a set-up that is shared by all genes (the MINQUE weights and the quadratic-form matrices), and then tests each gene. With the default method = "davies", the set-up takes seconds and nearly all the time is spent on the genes: each needs four eigendecompositions and six products of n \(\times\) n matrices. Run time therefore grows with the number of genes, the number of kernels (11, or 1 for large data) and about the cube of the number of cells n.

Parallel computing

obj <- SIGNAL_test(obj, ncores = 20)                     # all genes, 20 workers
obj <- SIGNAL_test(obj, ncores = 20, parallel = "genes") # the same, explicitly
  • ncores defaults to all available cores: the Slurm allocation (SLURM_CPUS_PER_TASK) on a cluster, otherwise all cores of the machine.
  • parallel = "genes": the kernels are processed one at a time; each kernel’s set-up is computed once, then the genes are split over ncores forked workers that share it. Each worker adds only a few n \(\times\) n matrices of memory.
  • parallel = "kernels": the kernels are processed in parallel, each worker with its own set-up. Useful with method = "liu" or "davies_liu" and few genes, whose set-up is costly, but each worker needs about 20–50 n \(\times\) n matrices.
  • parallel = "auto" (default) chooses between the two from the numbers of kernels, genes and cores, and limits kernel workers to the available memory.
  • With verbose = TRUE, a progress bar shows the genes of each kernel.

The workers are forked processes (pbmcapply::pbmclapply). Forking does not work on Windows, so there SIGNAL runs on one core; use Linux or macOS for parallel runs.

BLAS threads

With a multithreaded BLAS (OpenBLAS, MKL), SIGNAL runs each kernel’s set-up with ncores BLAS threads and the workers with one thread each, and restores the previous setting afterwards. Outside the tests, set one thread before starting R so that the other steps stay within the allocation:

export OPENBLAS_NUM_THREADS=1 OMP_NUM_THREADS=1 MKL_NUM_THREADS=1

One spatial kernel for large data

With more than 6,000 cells, SIGNAL_kernel() builds one Gaussian spatial kernel instead of the panel of 11, which reduces run time about 11-fold:

obj <- SIGNAL_kernel(obj)                         # automatic: 1 kernel above 6,000 cells
obj <- SIGNAL_kernel(obj, approximation = TRUE)   # always 1 kernel
obj <- SIGNAL_kernel(obj, approximation = FALSE)  # always 11 kernels
obj <- SIGNAL_kernel(obj, max_cells = 10000)      # change the threshold
obj <- SIGNAL_kernel(obj, bandwidth = 0.05)       # fix the kernel bandwidth

Memory

One n \(\times\) n matrix takes 8 n² bytes:

Cells One n \(\times\) n matrix Main process Each gene worker 20 workers in total
1,000 8 MB < 1 GB < 0.1 GB < 2 GB
4,410 0.16 GB ~5 GB ~1.1 GB ~27 GB
5,520 0.24 GB ~5 GB ~1.7 GB ~40 GB
9,244 0.68 GB ~12 GB ~4.8 GB ~110 GB

If workers run out of memory, the operating system stops them and SIGNAL reports it; use fewer workers (ncores) or request more memory.

Splitting genes over cluster jobs

The genes are tested independently, so a large analysis can be split into batches, one per task of a Slurm job array, and the result tables combined afterwards. See the axolotl brain example.
